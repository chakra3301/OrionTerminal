## Implementation

- `src-tauri/src/draft_recovery.rs`: per-frontend-session private0600 JSON journal in0700 `<app-config>/draft-recovery/`, independent of SQLite failures. Native main-window-only commands validate version/identity/revision, item types and sizes; serialized atomic temp/sync/rename writes reject stale revisions. A new frontend lifetime rotates session identity and releases the previous ownership lock; late old writers cannot overwrite the new session. This also preserves earlier snapshots across a frontend reload.
- Session lock files exclude running sessions from review/export/discard. Unreadable ownership metadata surfaces an error rather than pretending no copies exist. Unknown/corrupt journal data is preserved, not overwritten or automatically pruned. Six Rust regressions cover owner exit, stale revisions/frontends, failed/oversized writes, independent sessions, incompatible data and private no-overwrite export.
- `draftJournal.ts` / `useDraftRecovery.ts`: collect actual staged note title/body and dirty **loaded** file buffers, including inactive panes. A150ms trailing debounce controls serialization/disk work; ordered coalesced writes acknowledge only captured snapshots. Later successful primary saves stage a clearing snapshot. Failures are visible and retryable; pending/failed recovery adds a normal-quit warning. Six frontend regressions cover collection, ordering, newer edits, failure/retry, clearing after uncertain acknowledgment, disposal and a fresh-ID note insert.
- `RecoveryPanel.tsx` / `recoveryStore.ts`: **Review local draft recovery** in Spotlight; native HTML modal with text-only limited previews. Recovery exports to a **new** file (existing destinations refused) or inserts a **new** note in one SQL statement. Original notes/files are not updated. Recovered notes do not copy parent/collection/tag metadata. Recovery copies remain until explicit session-level discard; no automatic replay into live data. Empty/current-session-excluded and retained-session review, note/file copy and explicit discard paths were exercised natively (binary-specific evidence below).

Limits: last acknowledged copy only, not zero-keystroke-loss;150ms debounce and in-flight writes can be lost. Note body/file text limits4MiB each, whole journal16MiB/128items; review bounded to32nonempty sessions/1024directory entries, with visible manual-review errors rather than deletion. No automatic retention/cleanup of old locks, empty or crash-orphaned files. Copies are unencrypted and can contain sensitive text; do not upload them. Nested BlockNote/application-schema validation is not exhaustive. External assets, XDesign/FX/model drafts, unsent chats, other specialist state, power-loss durability and full-profile restoration are outside this slice. Quit without saving does not deliberately erase recovery copies.
