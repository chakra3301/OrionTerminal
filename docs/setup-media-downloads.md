## Use

1. Open **Archives → Downloads**, or Spotlight → **Download Video or Audio**.
2. Paste one public HTTP(S) media link and choose **Inspect link**. Paste alone makes no network request. Optional **Browser cookies** is off by default; selecting a browser/profile does not access it. Inspection/download each require their own native **Allow once** approval before cookie extraction.
3. Select **Video** or **Audio only**; choose among fourteen video/eight audio choices. Inspect real streams under **Exact source format** if desired. Optional **Clip a section** re-encodes a range locally after full transfer. **Play in Media** checks real video codecs and converts if necessary; turn it off to preserve source codecs. Choose **Download**.
4. A download started in this session saves to Media automatically on completion. Navigation away from Downloads does not stop it.
5. **Stop** terminates the downloader and descendants. Retry discards that job's partial files and starts again. Queued items additionally support **Pause transfer**, retaining partial files for a later explicit Run with real server-dependent continuation; conversion/postprocessing/saving are not resumably pausable.
6. History survives restart. Interrupted jobs do not resume automatically; files already ready for import offer **Save to Media**. Import failures retain the completed file for retry without another network download.
7. **Transfer controls** offers actual16–1048576KiB/s rate limits (blank = unlimited),0–10 retries and1–8 concurrent fragments. Fragments are pieces of one download, not concurrent jobs.
8. **Metadata, chapters & captions** adds optional source metadata, chapters (video/M4A), cover art (MP3/M4A/FLAC) and full-video subtitles. Choose one to five exact language codes; automatic fallback is off by default. Manual captions take priority. Captions+clips are refused rather than mistimed; MP4 text conversion may lose styling. All new switches default off. **Verified file extras** comes from actual file probes and a bounded keys-only subtitle-language receipt, not requested controls. Saved-file sidecars and local caption search are now available as described below; extras omitted at download time cannot be recovered locally. [Formats/evidence/limits](architecture/archives-downloads-embedding.md).
9. **SponsorBlock** is optional and off by default. For YouTube, explicitly mark selected categories as embedded video/M4A chapters, or remove them from the new copy. This contacts `sponsor.ajay.app` using a video-ID hash prefix and categories; hashing is not anonymity. Inspection makes no such lookup. Only sponsors are initially selected. Removal currently refuses clips/captions, and cuts may land near keyframes; originals remain untouched. A native bounded gateway validates service responses; actual output timing/categories are checked. Valid empty/404 keeps the whole file; malformed/unavailable results fail. [Privacy, formats and exact evidence](architecture/archives-downloads-sponsorblock.md).
10. **Download settings → New-link defaults** or **Save these defaults** persists format/playback/quality/duplicate/transfer/embedding/SponsorBlock choices. Clip ranges, exact format IDs and browser choices are never defaults. New inspections snapshot defaults; existing jobs retain their options.
11. **Storage & time limits** sets maximum final-file size, combined unfinished work, minimum free disk space and per-engine timeout. Defaults stay 2048/4096/512 MiB and 45 minutes; file caps up to 64 GiB are available, with at least twice the file cap as work headroom. Controls appear both per source and in saved defaults. Existing queued jobs retain their snapshots; different shared-work-cap cohorts wait for active jobs to finish. Larger caps are not reserved disk space. [Ranges, safeguards and evidence](architecture/archives-downloads-limits.md).
12. **Export a copy…** opens a native Save dialog after import. Filename is editable with the real extension kept; existing targets, source files and folder links are never overwritten/followed. Choose a physical folder, outside disposable download/authentication scratch storage. Media originals stay intact.
13. For a saved download or its Media player, **Captions & sidecars → Inspect saved file** reads actual local tracks/chapters. Select a supported text track to **Export VTT… / Export SRT…**, export chapter/metadata JSON, or **Index selected captions** for local keyword search. Clear removes only derived search text. Native Save dialogs and no-overwrite exports preserve originals; no remote access, cookies, transcription or AI. Archives sidebar now defaults to **Keyword only · no AI**; uncheck explicitly to use existing embedding-assisted search. [Exact authority, freshness, evidence and limitations](architecture/archives-downloads-sidecars.md).

14. **Library details** in a completed item's inspector or Media player lets you rename its library title, favorite it, copy its source link and review attribution. This never renames source/media bytes. Downloads offers Video/Audio/Favorites filters and searches saved titles/tags/filenames as well as source metadata.
15. The player exposes caption tracks actually available to WebKit. After **Inspect saved file**, chapter buttons seek in the existing player without starting playback/sound. Unsupported embedded captions still have export/external-player fallback; no invented player support.

**Batch links** queues1–50 public links with frozen saved defaults, without fetching on paste/admission. **Playlist → Review playlist** reads up to100 public entries; explicitly choose up to50 before staging. Review expires after10 minutes. **Add to queue** stages an inspected single source with its chosen settings. **Run queue** starts the current waiting group with1–3 work slots; newly added or returned items require another Run. **Hold queue** stops new claims while active items finish/save. Earlier/Later changes the exact waiting order while held; Cancel item removes its run intent. **Return to queue** does not silently restart a paused item. Native queue/publication continues across view navigation; queued/paused entries stay held after process restart, and interrupted Retry starts clean. Queues/playlist scans never inherit browser-cookie permission. Live/upcoming streams and subscriptions remain unimplemented. [Queue policies/acceptance](architecture/archives-downloads-queue.md). Browser-cookie routing is implemented for macOS but real credential extraction/native permission-dialog acceptance has **not** been tested by the agent; it needs separately approved owner smoke. Not all supported yt-dlp sites will work at all times. Resolution ceilings apply when dimensions are known; unknown-dimension direct media remains downloadable. With Play in Media off, source codecs/containers may require an external player. Conversion cannot improve source fidelity. Skip duplicates checks a separate native archive that survives history and Media removal. Source/preset/playback/quality/range/exact-format/embedding/enabled-SponsorBlock variants are distinct; generic filename identities are scoped to the source URL, not unrelated hosts. **Forget source archive** explicitly forgets all variants for that source without deleting Media/history; disabling Skip duplicates permits an intentional copy.

## Browser privacy and posters

Chrome/Chromium/Brave/Edge/Firefox/Opera/Vivaldi/Safari are explicit choices. Chromium-family defaults use `Default`; named profiles accept only a bounded folder basename, never arbitrary paths/CLI/keyring expressions. Blank Firefox selects its most recently modified cookie database; Safari offers fixed system/container stores. Permission names the exact source/job/operation. Inspection consent is not reused by Download or Retry; local playable copies never use cookies.

External yt-dlp may read other sites’ cookies in that profile and temporarily copy its database. A separate0700 scratch area (not assets/media work), sampled64MiB/128-entry budget, native advisory profile lease, engine reaping and cleanup isolate this from publication. Idle listing retries orphan cleanup after abnormal restart and does not remove a leased active cookie area. Authenticated diagnostics are redacted before history/UI. No raw cookies or browser choice enter preferences/history/model prompts; no claim of memory zeroization, a subprocess/network sandbox, or actual-browser security acceptance.

Inspection can optionally fetch a public HTTPS JPEG/PNG source preview natively: DNS-address validation/pinning, no redirects/proxies/cookies/browser headers,6s/256KiB/dimension bounds and16-entry30min profile-path-bound process cache. The WebView receives raster data, never a remote image URL; failures show the normal icon. Source thumbnail URLs are not persisted or sent to AI. Video completion and actual embedded MP3/M4A/FLAC audio covers generate small320px local JPEG posters, with file-only FFmpeg and bounded validation. Audio art extraction deliberately does not seek. Media/Downloads/player use the saved identity-bound poster; asset deletion cleans it. Poster/media publication shares the receipt transaction and retains retryable bytes on DB failure. Source previews are session caches; saved posters persist. No real thumbnail-site or audible/player acceptance claim.

## Automatic organization

- Native import classifies into Media **Video** or **Audio**, with `downloaded`, media-kind, source-host and up to five sanitized source-provided tags.
- Title, creator, bounded description and original URL are retained. Saved titles/tags participate in the existing Archives search/indexing flow.
- If **Background AI → assets/media tagging** is enabled, a newly imported item also goes through the existing Archives provider route for topic tags. Existing local/manual tags are retained.
- AI receives title/filename/kind/size and bounded creator/description metadata, **not the video/audio file or its source URL**. This feature does not enable background AI or change its provider selection.
- With AI off, deterministic tags and Video/Audio categorization still work. This is not automatic assignment to arbitrary user collections or mood boards.

## External engine setup

No new npm/Cargo dependency or Stacher code is included. Engines are separate user-installed executables; Orion does not download/update them automatically. Do not copy Stacher's private profile or bundled assets.

The approved private engine location is:

```text
~/.local/share/orion-tools/media-downloader/bin/yt-dlp
```

Detection also checks `/opt/homebrew/bin`, `/usr/local/bin` and `/usr/bin`. FFmpeg and ffprobe must be in the same directory. Compatible Node is selected explicitly for installed EJS support. Ambient shell PATH/config/cookies/proxy credentials are not imported into the downloader environment.

On this owner's macOS arm64 machine, installation used CPython **3.13.3**, **yt-dlp 2026.8.19** and **yt-dlp-ejs 0.8.0**, with a reviewed PyPI wheel plan and hash-locked dependencies:

```sh
# Only for a new private environment; do not overwrite an existing environment.
umask 077
python3 -m venv "$HOME/.local/share/orion-tools/media-downloader"
"$HOME/.local/share/orion-tools/media-downloader/bin/python" -m pip install \
  --disable-pip-version-check --only-binary=:all: --require-hashes \
  -r scripts/media-downloader-macos-py313.lock.txt
```

The lock is specific to the inspected macOS/CPython wheel selection. Other platforms/Python versions need a separately reviewed lock, not bypassing hashes. No global Homebrew upgrade/install was performed. Existing FFmpeg/ffprobe **7.1.1** and Node **24.16.0** were retained. Engine updates require an explicit reviewed action.

Licenses are distribution-specific: the source/PyPI yt-dlp package is Unlicense; EJS carries its own third-party notices; optional dependencies include GPL components such as mutagen. This machine's FFmpeg build enables GPL. The engines are **not bundled or redistributed with Orion**. Any future bundled installer needs its own license/notice/source review.

## Bounds and limitations

- Up to3 native concurrent queue work slots (default1); a manual source operation still uses the single-link gate. 100 history entries, 4096-character URL, 4 MiB inspection output, 64 KiB diagnostic output and bounded progress lines/logs.
- Explicit HTTP(S) public hostnames only: no embedded credentials, custom ports, literal IPs, localhost/private initial DNS answers, files or CLI-option input.
- **Not a network sandbox.** Initial DNS validation does not constrain extractor redirects, media/CDN requests or DNS rebinding. Do not treat this as safe automated ingestion of hostile links. Native process privileges are those of the user.
- Fixed argv, no shell; ambient yt-dlp configs/plugins, automatic updates and remote executable components are disabled. Cookie extraction is disabled unless a validated browser choice receives native one-operation approval; HOME stays private and no cookie export/config is written.
- TLS checking remains enabled. No DRM/paywall bypass.
- Inspection process budget 90 seconds plus bounded DNS. Transfer, caption remux and conversion each use a validated 1–1440-minute snapshot (default45), not a whole-job deadline. Full process-group cancellation on Unix; non-Unix descendant behavior is not accepted/tested.
- Configurable final-file16–65536 MiB, shared unfinished-work32–262144 MiB (at least2× file cap), free reserve512–65536 MiB. Defaults remain2GiB/4GiB/512MiB. Work/disk sampling every500ms can overshoot and is not a hard quota or reservation. Publication includes room for the whole pending copy plus the job's reserve; recoverable ready files stay ready if admission fails. Manual export has its own512MiB reserve/64GiB absolute ceiling. [Full policy/evidence](architecture/archives-downloads-limits.md).
- Private generated job directories; no-follow regular-file publication; atomic no-overwrite link from synced temporary file; stable job/asset ID. Native transaction commits asset, local tags, independent archive and completion receipt together. The previous 512 MiB generic asset-import cap is unchanged.
- Partial files are retained until Retry/Remove. Remove history never deletes a saved Media asset or its independent download archive. Ready files must be imported before removing their entry.
- Abrupt power loss, hostile simultaneous filesystem mutation, orphan temp-file cleanup, broad site compatibility, real large transfers and full-profile rollback remain unaccepted. Source URLs are stored locally in history/asset rows and may be included in normal database backups.
