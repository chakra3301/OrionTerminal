# Archives Downloads — durable queue / batch / playlist slice

Implemented 2026-10-06 under the already-approved Stacher parity rebuild. **This closes implementation of the bounded queue/batch/playlist slice, not full tool parity or broad native acceptance.** Owner-confirmed existing-clip recovery remains closed; no owner original or derivative was reread/reconverted.

## Native authority and workflow

- `0038_media_download_queue.sql` stores native job membership, order and a retained-transfer resume flag, with history-deletion FK cleanup. Batch admission validates all 1–50 public URLs and capacity before one transaction; repeated links refuse rather than silently dropping entries. Each entry snapshots saved defaults. It initially performs **no inspection, download or AI call**.
- **Run queue** grants a process-local snapshot of waiting/ready identities, with 1–3 concurrent work slots. Each item is inspected separately, checked against the independent archive, transferred with its frozen options, normalized/probed, given an optional local poster, and published through the existing asset/tags/archive/completion transaction. A source already transferring or waiting for a publication receipt reserves its output variant; unrelated variants continue. Failed publication retains ready bytes for explicit Save/another Run, without a tight retry loop.
- Newly added or resumed entries require another Run even while a previous group is active. **Hold queue** invalidates future claims; already active work finishes and saves. Waiting order can change only while held, using an exact current-set transaction. **Cancel item / Stop** withdraws the job's run intent and terminates active subprocess groups.
- **Pause item** holds waiting work. **Pause transfer** cancels and reaps an active yt-dlp transfer before recording `paused`; its private partial files are retained. Return to queue preserves that job's options and uses real `--continue` on the next explicit Run. Inspection, conversion, postprocessing and publication are not falsely advertised as resumably pausable. Failed/stopped/interrupted Retry starts clean; local playable copies never join the remote queue.
- Resume is server-dependent: yt-dlp may restart instead of accepting byte/fragment continuation. A changed remote resource may require a clean Retry. No guarantee of resumability for every site/format. **Cold startup never reconstructs Run authority**: queued/paused entries stay held; formerly active jobs become interrupted and require explicit Retry. Completed files/receipts retain normal restart recovery.
- Native shared-owner profile leases coordinate operations and orphan recovery across cooperating Orion processes. The empty lease inode is not removed. Explicit last-owner unlock avoids unrelated concurrent fork/exec descriptor inheritance keeping a finished operation spuriously leased. Cookie scratch has the equivalent semantic unlock only after scope cleanup and engine completion; tests use fabricated cookie paths, not real credentials.

## Playlists and consent

`playlists.rs` invokes bounded `--flat-playlist --yes-playlist --playlist-end 101` inspection only after **Review playlist**. Up to100 entries are displayed; nested/restricted/unsafe/missing-link entries are not selectable. Known YouTube/Vimeo flat IDs are reconstructed through fixed URL rules, never interpreted as CLI arguments. A native, profile-bound immutable review expires after10 minutes, is capped at8 reviews, and queues only explicitly selected1–50 indices. Native admission accepts review identity/indices, not editable client URLs. A committed selection consumes its review; failed admission does not. Stop scan has independent cancellation even while its inspection command is pending; late reviews cannot take over the UI.

**Queues and playlist scans are anonymous. They never persist, reuse or inherit browser-cookie approval.** A restricted entry must use the existing single-link workflow with fresh source/job/operation native Allow once. Queue grants do not enable Background AI, upload media or grant model tools. After an explicit current-session Run receipt completes, the frontend adopts the native Media asset once, using existing consent-gated bounded text tagging. Reopening history alone does not invoke tagging/imports.

## Bounds / UI

`queue.rs`, `lease.rs`, `playlists.rs`; `QueueTools.tsx`, `downloadStore.ts`, `downloadTypes.ts`, `Downloads.tsx`, `downloads.css`.

Single link, Batch links and Playlist surfaces share the compact themed workspace. Drafts/reviews survive switching source surfaces, FIFO rows match actual queue order, per-item pause/cancel/return/reorder controls and concurrency/hold/run actions call real native APIs. Errors keep drafts/ready bytes; completed-but-unadopted assets offer explicit Media refresh. Queue/scan work participates in the existing plugin lifecycle guard even while waiting for a matching publication receipt.

History remains100 entries. The original queue slice used2GiB final/4GiB combined work/512MiB free defaults; these remain defaults, but the later [storage/time slice](archives-downloads-limits.md) adds validated per-job configuration. The **combined unfinished native download root** is sampled every500ms, not a separate allowance for each worker. Different shared-work-limit snapshots wait for the active cohort to drain; publication uses the original job's reserve and ready files remain recoverable after admission refusal. These are sampled safeguards, not hard quotas/reservations or accepted large-4K transfer proof. Rate/retry/fragments remain real frozen options, distinct from concurrent jobs. Native engines were not updated or redistributed; no new dependency.
