## Persistence and identity

Migration `0031_installed_skill_packages.sql` is appended and registered in `src-tauri/src/lib.rs`. No previous migration changed.

- `skills.id` remains the installed identity, generated by the host as `imported:<ULID>`. An upstream name cannot overwrite a builtin or user skill.
- Imported `skills.instructions` is deliberately empty and `tools_json` is exactly `[]`. Package bodies cannot accidentally enter legacy background/app-wide composition. `skillsStore` joins strictly validated package metadata into its in-memory view; generic save/delete APIs reject the reserved identities.
- `skill_package_versions`, `skill_package_files` and `skill_package_links` provide immutable backing and the active-version/enabled pointer. Current plus **one previous** version are retained; a subsequent update prunes older version rows/files atomically. Rollback swaps the pointer without changing the installed ID or enabled state.
- `skill_package_receipts` binds the consumed candidate ID/hash to its installed identity. Duplicate completion cannot create a second install. Removed/pruned/changed-version receipts cannot silently resurrect old installs. Consumed candidates cannot be staged again; a fresh inspection creates a new review.
- Promotion validates staged bytes/manifests and expected hash, creates/updates the host-owned identity/version, retains rollback, and consumes staging in one immediate SQLite transaction. Updates require target ID + expected active version. Failures preserve the prior install and staged candidate.
- Updates require matching declared name, entrypoint and canonical repository URL, or local source label. Local labels are **not** authenticated publisher/path identity. Acquisition still has the prior Git SHA/signature verification limits; every update needs explicit review.
- Installed quota: **24 skills, two retained versions each, 128 MiB total package payload**. Existing per-package bounds still apply. Small installation/removal receipts remain retained; logical deletion is not secure erasure and existing SQLite backups may retain earlier bytes.
- Ordered store writes publish only after native acknowledgement and successful joint hydration. Unknown/failed hydration or an ambiguous mutation keeps the prior view and blocks further writes until reload; it does not seed an empty replacement. The existing SQLite backup mechanism includes package tables/BLOBs, but no complete backup/restore acceptance is claimed here.

## Context and cancellation boundary

`src/features/intake/skillActivation.ts` and `dispatchSend.ts` resolve only reviewed installed IDs/versions. Native context reads check current ownership/enabled state, version equality, manifest/blob hashes and package-relative paths inside a SQLite read transaction. No extracted workspace paths or new model resource tools exist.

- Attachments: Markdown, plain text, JSON, CSV and attribution text; no executables/shebangs, inactive code, opaque data, NULs, path traversal or undeclared files. UTF-8 bytes are preserved without trimming. Other file types remain stored and may have an escaped local preview, but are not activated.
- At most eight optional resources per skill; **256 KiB combined skill text**. Incomplete/foreign/stale responses fail before dispatch. Large instructions are rejected when over budget, never silently shortened.
- Current provider model metadata has no verified context-window field. The user must confirm a 32k/64k/128k/200k-or-larger model capacity. Preflight conservatively counts UTF-8 bytes across host-visible instructions, prompt and conversation, reserving 8,192 tokens for output/headroom. This is **not a tokenizer or automatic model-capacity discovery**; hidden CLI/project instructions and provider-specific overhead remain acceptance limits.
- Review is bound to model/provider identity. Provider changes or cancellation during native preparation cannot start a late request. Imported turns never resume a prior CLI session, and their emitted session IDs are not granted resumable ownership (existing ownership is revoked). If reset persistence fails, the UI requires a new chat after restart. Already transmitted context cannot be retracted; previous assistant/user messages remain ordinary conversation history.
- Foreground leases in the shared store require **Stop before update, rollback, disable or remove** while an imported response is active. They cover preparation through the existing exit/cancel lifecycle. This is a trusted-frontend lifecycle interlock, not a general native execution sandbox or broker for external resource handles.
- Orion publishes the user message/receipts only after preflight. Budget/compatibility failures retain the draft without a phantom chat message. Stop or unmount during app-context preparation prevents late dispatch and clears pending busy state. Fresh sessions receive the app preamble, including the first normal turn following an imported turn.

IPC routing contracts were tested for Claude CLI, Codex CLI, Gemini CLI, Cursor SDK, OpenAI, Google and OpenAI-compatible text runtimes. **No new live route quality/authority acceptance** follows from mocked IPC tests.
