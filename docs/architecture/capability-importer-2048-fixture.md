### Runtime findings

- Classic script order: bind → classList → animation-frame polyfills → keyboard input → HTML actuator → Grid → Tile → local storage → GameManager → application. Application schedules `new GameManager(4, KeyboardInputManager, HTMLActuator, LocalStorageManager)` through requestAnimationFrame. No modules or external runtime library found in these files.
- Game starts with two random tiles; new tile is2 with90% probability, otherwise4. A successful move merges each participating tile once, scores the merged value, inserts a random tile, checks available moves, and saves/actuates. Invalid moves do not add tiles.2048 opens the win overlay; Keep going permits larger tiles. These are **source observations, not executed acceptance**.
- Input listens on the child document: arrows, Vim/WASD, R restart, click/touch buttons and swipes. The same modifier guard excludes modified moves and R restart; there is no editable-target exclusion (INPUT/TEXTAREA/contenteditable). Adapter needs explicit focused-child/editable/modifier checks and focus-visible keyboard buttons; no parent key forwarding or forced focus stealing. Focus/window isolation still needs native testing.
- Actuator uses DOM creation/textContent for numeric tiles and scores; clears tile children and schedules animation frames. Styles are committed500px/280px board layouts with520px breakpoint,100ms moves and200ms tile effects. Canonical visual reference should be committed CSS, not an unapproved Sass rebuild.
- Selected JS contains no observed fetch/XHR/WebSocket/beacon/eval/worker transport. HTML contains four external attribution/play links, stylesheet/icon/mobile-image links, and local script tags; CSS imports font CSS. README has an external screenshot. No links/images were followed as game content. This bounded inspection is not a vulnerability scanner or a network-behaviour test.
- `LocalStorageManager` probes localStorage with try/catch, then uses volatile `window.fakeStorage` if denied. Best score and JSON gameState are synchronous; JSON parsing/grid loading lack schema validation and storage writes have no failure UX. Opaque SDK durability cannot rely on this fallback. Game-over clears the saved board; New Game retains best score. Keep going changes the in-memory flag without saving until a later actuation.
- Rakefile only updates an appcache timestamp; it is not a Sass build/install command and was not executed. SCSS helper explicitly credits Sassy Math. No Rake/Sass/Compass/npm setup is needed for the proposed captured-classic-script adapter.
