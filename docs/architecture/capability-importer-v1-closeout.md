## Real audit fixes

1. **Local SDK disabled-install receipts:** previously accepted the raw native return without checking exact manifest/fingerprint/disabled/grants/no-workspace/quarantine/time and permitted another attempt after an uncertain native response. Now shares a strict pure disabled-receipt parser with prepared installs; manifest object-key order is irrelevant, grant arrays must be flat and exact. Missing/future/foreign/enabled/overgranted/malformed receipts block Manager mutations pending explicit recovery. No activating legacy fallback or startup.
2. **Local SDK review lifetime:** hydration/recovery now gate installation. The owner-scoped UI lease is checked before and after synchronous busy subscribers, immediately before irreversible native IPC. Closing before handoff prevents it; a confirmed receipt after dismissal still belongs to the global Manager.
3. **Queued skill review lifetime:** a queued Skill Codex install checks the live UI lease when it reaches the queue and after synchronous mutation subscribers. Dismissal before IPC leaves known backing hydrated; uncertainty after IPC retains old view and requires reload. Confirmed late installs still hydrate globally. No freeform instruction/tool authority introduced.
4. **Cancellation settling:** skill picker/inspection, repository document acquisition and advisory analysis no longer unlock a second operation while a cancelled request/native folder dialog is still settling. Late results stay ignored/released; effect-replay ownership cannot unlock a newer operation. External recipient changes cannot overlap or pretend to cancel committed assessment saves.
5. **Exact skill text:** foreground preflight now recomputes SHA-256 of every full selected text part, not merely its length and claimed hash. Same-length corruption is rejected before user-message publication/provider dispatch. Actual111,157-byte Taste/Stitch context remains preserved with zero tools/null Action and no truncation.
6. **Known-recipe UX:** inspecting the known2048 repository no longer says all app installation is unsupported. Navigation explicitly identifies a separate fixed reviewed recipe, not necessarily the resolved revision; it starts no fetch, conversion or install. Unsupported repositories retain the honest unsupported result.

`src/plugins/pluginInstallReview.ts` is a pure shared boundary; prepared validation no longer imports a React intake component. Existing themes/materials/radii/SDK/CSP/native grants remain unchanged. Focused regression tests cover leases, uncertainty/recovery, altered receipts, cancellation settlement, exact text, confirmed late receipts and no-fetch navigation.
