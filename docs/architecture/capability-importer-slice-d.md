# Incubator Slice D1 — reviewed package analysis

2026-09-16. **Bounded implementation, not full Slice D/upstream parity or native/live-provider acceptance.** Owner requested continued features before UI polish. Builds on [A/B acquisition](incubator-repository-intake.md) and [C installation/activation](capability-importer-slice-c.md).

## Delivered

- Both Incubator and Settings expose optional analysis of an already-staged skill package. Choosing a model, selecting files and preparing a preview are local operations. Analysis begins only after a separate reviewed-upload acknowledgement/click.
- `src/features/repoAnalysis/{contracts,service,sourceText}.ts` is a headless, injected-runner seam: immutable source/host inputs, goal/risk/stack-fit/integration-cost briefing, strict result parsing and host-authored evidence. It imports no Archives stores, jobs or UI. The unchanged MIT-attributed RepoLens framing helper moved here; Archives re-exports it and retains its existing prompt/workflow. Attribution scope was extended in the notice and license ledgers. This is selective reuse of goal-evaluation concepts, **not a wholesale upstream port or a new static scanner**.
- `analysisSource.ts` reads only explicitly selected staged files, verifies original UTF-8 byte counts/SHA-256 and performs limited credential-pattern checks on their complete contents before excerpting. One to four non-opaque files, each within the existing 256 KiB read limit; first 8,000 UTF-16 characters per file, sanitized for framing. Inventory/hash metadata for the selected package subtree is included. Truncation is disclosed; this is deliberately not C's full-instruction activation path and not a whole-repository audit.
- App-owned system instructions and user payload are previewed. Input is bounded to 80 KiB UTF-8; output to 32 KiB UTF-8; conservative 8,192-token overhead reserve and explicit 128k-or-larger context confirmation. This is not verified model metadata/tokenization, nor a guarantee about connector/provider-added context. Narrow credential detection and prompt framing are not comprehensive DLP or security clearance.
- One-shot, in-memory consent expires after ten minutes and binds source/excerpts, goal, enabled core-app profile, model/provider configuration and analyzer version. Changed inputs, unavailable staging, Stop, unmount or stale callbacks prevent publication; the final pre-dispatch check runs after asynchronous preparation. No automatic retry or paid repair call.
- `runExplicitModelAnalysis` bypasses surface defaults and saved-agent/imported instructions. Existing bounded streaming lifecycle, fresh analysis workspace, cancellation and **empty grants** are reused—not RepoLens's special Claude branch. 180-second timeout, no resumed session input, no image attachment or executable plan. The native HTTP path uses the new **`runtime_send_reviewed`** command: checks provider ID/kind/normalized endpoint/key reference against the saved configuration before credentials or upload, rejects tools, and retains configuration-change checks. Old binaries fail closed without falling back to ordinary `runtime_send`. CLI/SDK routes retain their fixed connector routing and frontend preflight. This binds configuration, **not an immutable credential value/account identity**.
- Model output can only be advisory prose/enums. Unknown fields, permission/`verified` additions, malformed JSON, invalid evidence bases and fabricated path/quote citations are rejected. Quotes must match submitted sanitized excerpts; a match is not independent factual verification. Model recommendations cannot install, approve rights, run a trial or grant permissions. Security, vulnerability, functional and license-clearance status is explicitly **not verified**, including when the model reports no blockers.
- Explicit local saving uses the existing `app_state` key `intake.analysis`, not a capability registry. Up to eight 32 KiB evidence records, no silent eviction. Stores hashes, provenance, selected model/provider fingerprint, goal, coverage and the assessment (including quoted findings), without separately retaining source/prompt bodies or provider credentials. Source text quoted in findings is retained. Confirmed removal affects only this history; existing backups may retain records. Serialized durable-before-visible writes, strict versioned hydration, retained failed views and reload-before-retry behavior. Every saved result is historical; there is no implicit cache hit/reuse as current verification or install authority.

## Verification actually run

- TypeScript: `npx tsc --noEmit`.
- Focused frontend: **84 tests in 12 files** covering preparation/consent, immutable excerpts, credential hints, citations/schema, stale/cancelled results, UI approval/escaped output/explicit save, provider changes, history failures, distinct IPC/no fallback, existing dispatch routes and unchanged RepoLens framing.
- Native: `cargo test --manifest-path src-tauri/Cargo.toml --locked --lib runtime::policy::tests -- --test-threads=1` — **5 passed**, including reviewed recipient/key/kind mismatch, zero-tool enforcement and malformed bindings. In-memory provider fixtures; no network transport acceptance.
- Logs: `/tmp/incubator-d-tests.log`, `/tmp/incubator-d-native.log`. Pre-session dirty hashes: `/tmp/incubator-d-before.json`.

No new provider/repository requests, dependency installation, repository script execution, production DB/app access, broad release build, commit or release. Frontend persistence tests use mocked database boundaries; they do **not** establish a packaged database restart/restore. C's earlier real taste/Stitch temporary-SQLite evidence remains separate.

**Follow-up:** [D2](capability-importer-slice-d2.md) now supports explicitly fetched public-GitHub root documents without skills, while retaining separate installation authority and reading v1 history. The D1 limits/results above remain historical evidence.
