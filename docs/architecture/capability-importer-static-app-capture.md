## Native boundary

`src-tauri/src/intake/github/static_apps.rs` and `static_apps/store.rs` reuse existing public GitHub URL/commit/tree/response/client policy and shared job registry. Native commands: `intake_static_fetch`, `intake_static_cancel`, `intake_static_list`, `intake_static_read`, `intake_static_discard`. An updated binary is required; none was packaged or launched here.

- Fetch accepts only **2048-classic-v1**, not arbitrary URLs/recipes. The compiled shared declaration enumerates three fixed public repository pins and exactly **24 files / 172,077 bytes**, including fonts/notices. Unknown recipes fail before requests. No clone, authentication/proxy/redirect, README-link follow-up, hooks/compiler/package-manager/submodule or upstream-code evaluation.
- Resolve exact commits and bounded complete recursive trees through existing transport. Original tree `693fbb47db2d71aa65cc0e566a288473970233e6` must match. Each requested file must be a unique exact ordinary blob with the declared Git-blob ID/size, recorded original mode and ordinary directory ancestors; links/submodules/case ambiguity fail. Ancillary modes come from their resolved trees, not the historical fixture assumption.
- Download only these declared paths from fixed public raw GitHub endpoints. Verify exact byte count and SHA-256 independently of tree metadata; known Git-blob IDs are checked against the tree. Text is UTF-8/NUL/shebang checked; bounded existing secret-pattern/LFS refusal remains. Frontend revalidation additionally recomputes Git blob SHA-1. Native does not introduce a second SHA-1 implementation or dependency. Neither check authenticates a publisher, signed commit, font conversion, compatibility, rights or security.
- Existing bounds: two active acquisitions/shared 256-entry job registry, 15-minute used/cancelled tombstones, 90-second acquisition deadline, fixed client connect/request/stream/tree bounds. Partial/interrupted/failed/cancelled acquisition does not publish. Fresh IDs required; there is no background resume.
- Cancellation and complete durable source publication have one shared-lock ordering point. Cancellation arriving before publication wins, including a work-ready race; publication already won is not rolled back by a later Cancel. Source publication is synchronous, input-bounded transaction work with a 500ms SQLite **busy** timeout, not a wall-clock disk-I/O deadline. Async cancellation delegates through a blocking worker so the host UI thread does not wait on that publication lock. Uncertain commit errors require reloading captures, never automatic retry or deletion.

## Local immutable source vault, not an installed registry

Append-only migration **0032_static_app_sources.sql**, registered as schema32, adds a dedicated source table to the existing local app database. **No skill-table reuse or package/grant/lifecycle mutation.** Source packets are inert base64/text database data, not filesystem source trees or executable package directories; there is no new caller-controlled path/file traversal/publication operation. Existing host database/profile access and backup protections apply; this slice does not certify database filesystem permissions or symlink defenses.

- At most **eight captures**, no automatic eviction/expiry of saved records; packet bytes ≤256KiB, encoded complete stored record ≤384KiB. Save validates all existing bounded records within an immediate SQLite transaction. Identity conflicts, invalid/future saved data or capacity refuse mutation without replacing previous captures. A trigger forbids updates; new capture or separately reviewed discard only.
- `sourceHash` matches the frontend canonical complete input evidence hash, including actual modes. Separate `captureHash` binds capture ID/version/time, pinned repository/tree inventory, source hash/byte total and exact ordered packet data. These are source integrity metadata, **not recipe/output hashes, native package inspection fingerprints, permissions or execution authority**.
- Reload validates row indexes, bounded encoded record, versions/origins and every source byte against the owned declaration before returning. Oversized payloads are not materialized; corrupt/future entries block collection writes. Read/discard bind the selected capture hash. Discard removes only the source record, not installed code/data/preferences; backups can retain prior bytes, no secure-erasure claim.
- `src/features/staticApps/capture.ts` strictly copies own descriptors/dense arrays before awaiting, validates the complete packet through `validateStaticSource`, compares canonical source/capture identity, freezes detached summaries and returns the existing local validated-source seam. Explicit fetch/cancel/list/read/discard only; no web/local/legacy/provider/install/enable fallback or implicit calls. UI lifetime/disable/cancellation orchestration is still to be wired.
