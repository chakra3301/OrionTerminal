# Archives Downloads — saved-file sidecars and caption search

Implemented continuation of the approved Stacher-parity build; **not whole-tool parity or live/native-dialog acceptance**. Requires native schema39. Other remaining work is tracked in [the parity inventory](archives-downloads-stacher-parity.md).

## Working surface

**Captions & sidecars** appears for a saved download and in its Media player. Merely rendering/opening the disclosure does not inspect files, extract text, search, access remote sites, read cookies or invoke AI.

1. **Inspect saved file** probes the existing local asset. A short-lived native review identifies its actual subtitle tracks, codecs/language, duration and chapters. Requested download options are not evidence that a file contains captions. Bitmap/unsupported subtitle tracks stay visible but cannot be selected for text extraction.
2. Select one supported actual track; **Export VTT…** or **Export SRT…** converts that track to a standalone text file. **Chapter JSON…** exports the actual saved timeline. **Metadata JSON…** exports bounded title/creator/description and actual file/stream/chapter facts—not arbitrary stored JSON, raw transfer-URL fields or native filesystem paths. Source-provided text can itself contain URLs; it is untrusted content, not a network request.
3. Each export opens a native Save dialog. The returned path is never accepted from frontend IPC. Cancel publishes nothing. The pinned physical-folder, exclusive0600 temporary copy, sync and no-clobber publication policy is shared with media export; existing targets, links and disposable download/authentication scratch destinations refuse. Media bytes are never rewritten.
4. **Index selected captions** extracts one track and replaces that asset's previous local caption index transactionally. **Clear caption index** removes only this derived search text, keeping original media, exported sidecars and ordinary title/metadata search. Indexing/search do not call AI or enable providers. Authorized archive-search tools can return indexed text, as the UI discloses.
5. The inline search searches caption-indexed media using local keywords and routes selected results into Archives. The main Archives sidebar now defaults to **Keyword only · no AI**, covering titles, existing searchable metadata and indexed captions. Unchecking it explicitly restores the existing embedding-assisted path; keyword mode preserves disabled-app visibility filters.

This reads extras already saved inside the media. It **cannot recover subtitles omitted at download time**, fetch a new source language, OCR bitmap captions, transcribe audio, attach exported sidecars to the player, or create acquisition-time standalone captions without embedding them. Those distinctions are not hidden behind successful export/index messages.

## Native authority and source lifetime

- One caption/sidecar mutation/probe operation at a time; native profile advisory ownership is shared with the downloader. Operation IDs are validated, reviews are profile-bound, capped and expire after10minutes. Each operation re-resolves its saved asset and verifies the inspected source revision. No raw source/destination path or stream selector is accepted as authority from the renderer.
- Local source files are read-only, non-empty regular files within the existing64GiB absolute ceiling. No symlink/hardlink or replaced/disappeared source is accepted. The extraction backend currently supports64-bit macOS/Linux, verified on macOS arm64; other targets refuse instead of falling back to an unpinned path. The opened descriptor is pinned; its parent descriptor stays close-on-exec. Only the exact descriptor is inherited by the child through `pre_exec`; its offset is rewound before every child so probe→VTT→SRT does not inherit an EOF offset. Source descriptor/path identity is rechecked before/after processing and publication. Metadata identity is not a content hash or hostile-filesystem sandbox guarantee.
- FFprobe/FFmpeg use fixed argv, isolated environment, file/pipe protocols and an explicit media demuxer allowlist. No playlist/HTTP demuxer, browser, source URL, shell or model is involved. Native process cancellation/termination/reaping and90-second processing budgets use the existing collector. Export/probe output is capped at4MiB; chapter/stream inventories, finite duration/timing, text fields and serialized JSON are separately bounded.
- Cancellation is reachable while a Save dialog is open; close that dialog too. Early cancellation tombstones are bounded and profile-specific. During final synced file or SQLite publication, Cancel explicitly refuses rather than falsely reporting a stopped committed result. The active guard remains inside the blocking publication task, including awaiting/early-error lifetimes. Frontend source epochs and operation IDs reject late results and cancellation notices after an asset switch or newer operation.

## Text index and freshness

Append-only frozen `0039_asset_transcripts.sql` stores a versioned, source-revision-bound single selected track and bounded plain text. It extends existing asset FTS triggers: title/metadata updates retain captions; replacing an asset's file/kind or deleting the asset removes them, with foreign keys enabled or disabled. Updating/replacing/clearing captions replaces the search document without duplicates and retains the asset's ordinary searchable metadata. No owner SQL publication/repair workaround is used.

VTT/SRT parsing validates timestamps/duration, preserves chronological overlaps, removes supported markup and decodes bounded entities. Limits:4MiB input,20,000cues,4096UTF-8 bytes per cue and2MiB indexed UTF-8 text. Malformed/over-limit captions fail instead of silently truncating an index. Exported caption text and indexed normalized text are separate products.

Before shared frontend/MCP keyword queries, matching indexed files are checked against saved metadata revisions. Missing/replaced/in-place-changed files have only their old derived transcript conditionally removed; a newer concurrently published revision is not deleted. Existing archives without the optional transcript table retain normal search. Native caption results iterate one ranked SQLite cursor/read snapshot until20valid unique hits or exhaustion, avoiding invalid-row cutoffs and OFFSET skips during concurrent cleanup.

Successful native cleanup emits a profile-scoped, bounded asset-ID-only invalidation event. Archives shares one listener and marks mounted index panels unknown without automatically rereading files. Explicit index/clear/delete actions also invalidate search. If an index changes while a caption query is pending, its stale reply is discarded and the panel requests **Search again**. Inspect again to see current status. Out-of-band file changes are detected on matching keyword searches/inspection, not continuously monitored. No automatic transcription, embedding reindex or background media upload is triggered.
