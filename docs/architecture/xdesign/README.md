## Workspace layout

Design retains the original subtle 40-pixel square grid on the workspace background, with matching rulers. The grid is painted beneath the artwork in the viewport; it does not change saved page colors or appear in exports. Double-clicking an image enters the focused Image editor. Linked PSDs reopen the saved native document and version so layers are retained; embedded raster images are imported for editing. Text, vector and container double-clicks retain their upstream behavior.

The editor now prioritizes canvas space. File creation and import live in the project tab bar's File menu. Design uses six compact tool groups, including all eleven drawing tools; Image uses ten groups containing all twenty-seven image tools. Group selectors retain the last variant, including variants activated through design shortcuts. Search opens the complete existing action catalogs. The design partner opens from the tool rail and occupies space only when requested.

Design and Image share Layers on the left and Properties on the right. Both panels collapse independently and resize by dragging the boundary or using its arrow keys; Shift changes width in larger steps, Home/End select the bounds, and double-click restores the default width. Panel choices and widths persist locally and follow the user between modes. Without an explicit choice, the layer panel closes below 940 pixels of editor width and properties below 720; below 760, manually opened panels overlay the canvas. Panel changes preserve the mounted canvas and editor session.

The Design inspector exposes position, appearance, typography and layout according to the selected layer, with deeper arrange/component/variable/export controls in expandable sections. The Image inspector separates Layer, Image and Effects controls; painting options follow the active tool. Older project documents use the same collapsible panel system and retain their original canvas and inspector.

Develop, geometry, gradient, adjustment, common-filter, channel-compositing and text-geometry previews execute the requested command in an isolated native session copied from the pinned image state. The action catalogs provide access to long-tail engine operations. Having a command available in a generic parameter form is less complete than a polished dedicated workspace for that operation.

## Document and engine boundaries

`XDDoc` format 2 retains legacy pages and adds `pencilDocument`, `photoDocuments` and optional `photoDrafts` recovery records. Advanced designs store the authoritative OpenPencil graph, including images, variables, libraries and original Figma metadata. Node records omit engine defaults against a stored versioned template; graphs above 1MB use a streaming deflate envelope with bounded expansion. Legacy graph snapshots remain readable. They are not flattened into Orion's older shape union. Existing documents are not silently migrated.

Portable `.xdesign` files are bounded ZIP archives (512MB expanded total, 64MB metadata, 8192 assets). The native adapter verifies CRCs, SHA-256 inventory, asset paths, image/preview dimensions and smart-object draft links, writes staged assets, then opens the imported document under a new project identity. Legacy image resources are content-addressed and deduplicated. Linked smart-object sources are embedded in cloned backup bundles; the live document and its external links are unchanged. Missing sources fail the backup instead of producing a partial project. External links inside arbitrary HTML artifacts, external fonts, profile presets, local library catalogs and the checkpoint catalog are not bundled; graphs retain their materialized design data. Large backup packing still uses bounded in-memory buffers.

Project history stores checkpoints in SQLite, in the same transaction as the design autosave. Changed documents receive an automatic checkpoint on the next save after five minutes (20 retained, 128MB per project); unchanged snapshots do not create duplicates. Named checkpoints have a separate 50-version/128MB allowance and are retained until explicitly deleted. Restoration copies the referenced assets into a separate project, using the same validated archive pipeline. Project deletion removes its checkpoint records in the registry transaction. The image files remain retained because other saved checkpoints or live undo references may use them. Historical external linked sources are resolved when exporting/restoring; full external-file time-capsule semantics remain pending.

React continues to own Orion and the panels. Vue owns only the isolated canvas/input/text surface. It is removed when the project closes. CanvasKit and Inter assets ship locally; system fonts are loaded through native font discovery. Online font providers are disabled in this adapter.

The image engine resides in Tauri. Each mutation publishes an immutable `.pcraft`, PNG preview and view record before the project references the version. A failed command restores its previous engine document. Project save uses the existing atomic SQLite transaction. Native version checks and frontend registry checks reject stale image edits. Design undo changes the document version reference; reopening restores that version and its saved native past/redo history. Main Image Undo/Redo invokes native history and publishes the resulting version. Active/selected layers, channel target/visibility and mask view are restored from the view record, with validation against the saved document and defaults for older records. View-only commands update that record atomically without creating another pixel version or undo step.

Brush settings and brush libraries use the native preset store under Orion’s `xdesign-tools` profile directory. Gradient/style/shape/tool preset records use a separate atomic 32MB-bounded profile file; Pattern pixels use a separate atomic 128MB-bounded Photoshop `.pat` profile file. Shapes and tool presets share the profile records; selecting a tool preset restores supported Orion options and foreground color without sending sampled brush pixels back in its result. Every image session activates the current shared library before executing a command, preventing stale cached sessions from overwriting another document’s presets. Copied layer styles are shared in memory for the running profile. Tool/library changes have their native semantics and do not become image-pixel undo steps.

The detail viewer reads immutable native document Arcs and cloned channel view state without holding the session mutex during compositing. It renders only visible 512 × 512 regions, with two requests in flight and at most 64 cached tile records (up to 128MB of decoded RGBA when both color and selection coverage are present). Closing the editor or changing document/version/view disposes the cache; late results cannot install stale pixels. View keys also reject stale requests in the native host. Isolated fit previews use the same presentation rules, remain bounded to 2048 pixels per side and release their object URLs on view changes/close. These transient presentation buffers do not create disk versions, change layer pixels or affect normal composites and exports. Selection edges use the native mask's 50% threshold, merge collinear edges and cap complex paths at 16,384 segments per tile.

Photo links are stored in node plugin metadata as well as the project index. Node metadata is authoritative after undo, duplication or detachment. Exports clone the design graph and replace linked preview image bytes with native full-resolution renders. Rendering a preview does not flatten the saved image document.

Design document mutations use upstream undo or a bounded graph transaction; async mutations hold the design UI and project transition until completion. Declarative JSX is parsed into data and approved design helpers, then rendered through upstream `renderTree`. It does not invoke upstream `new Function`. Incremental property edits compare the generated baseline and desired declarative trees, preserve existing node identities/metadata/component links, reject stale or structural changes, and record one undo. Unambiguous text-size, touch-target and pixel-alignment lint fixes have a separate undoable action. Network-dependent tools and arbitrary script eval remain excluded until they have an Orion host adapter.

Component libraries live in the existing SQLite database under `xdesign.libraries`. Publication reviews a cloned source graph first. A single conditional SQLite upsert commits the entire immutable catalog only if it still matches the version reviewed by that window. Failed saves leave source keys/publication metadata untouched. Revisions retain a graph checksum and upstream content/revision hashes, and loading invalid storage fails without replacing it. Copies of a source project must publish a new library rather than overwrite the original project's library identity.

Library revisions embed full-resolution linked photo pixels and remove source-project photo references. Variable dependencies and aliases receive stable namespaces derived from their values, collections and modes; inherited node mode choices are made explicit before the component leaves its source page. Updating a revision therefore does not overwrite tokens used by older instances. Materialized definitions occupy a hidden internal page, while inserted instance descendants retain their source lock state and usable nested component references. Local token edits affect that consumer project, not the saved catalog.

Library update review runs on a clone, counts affected instances, removed-component retention, variant fallbacks and overrides that cannot map to a remaining layer, then saves the exact reviewed result. The source canvas must still match when the update is applied. Child overrides are matched by source identity/path, with unique name/type paths as a fallback. The whole update, its imported definitions/resources and its enabled revision form one undo entry. This is a local cross-project library workflow; it does not provide network collaboration or a shared team catalog.
