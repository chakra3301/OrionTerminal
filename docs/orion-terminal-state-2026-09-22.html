01 / Executive snapshot

A personal workstation with a real operating surface.

The product is one Tauri desktop window containing its own wallpaper, menu bar, dock, command search and movable app windows. The core loop joins a knowledge base, a code editor and a design studio, with AI routed through shared account and model controls.

Think

Archives 47

Notes, journal, projects, databases, media, learning tools and repository analysis in a personal knowledge space.

Build

Orion

A Monaco code workspace with files, terminal, preview, Git, language intelligence and AI editing.

Design

XDesign

Vector canvas, brand systems, generated webpages and decks, image tools, motion FX and a procedural 3D lab.

Read the status carefully. The public alpha is a specific published build. The repository also contains newer committed theme and workstation work plus uncommitted Incubator/plugin development. “Implemented in source” does not mean it shipped in the alpha or passed broad native acceptance.

Release footprint
3 core apps

Archives, Orion and XDesign are enabled on a fresh profile. Other built-in apps can be enabled in Plugins.

Additional surfaces
3 optional apps

Command Center, Hermes and the in-development Incubator extend the workstation beyond the core three.

Operating model
1 desktop shell

App windows are React surfaces inside one OS window, backed by native Rust services and local SQLite.

02 / The desktop shell

The frame that makes it feel like a place.

Orion Terminal treats the desktop itself as a product. The shell owns navigation, window focus, visual identity, notifications and settings so the apps share one coherent environment.

  • Windowing. Drag, resize, minimize, maximize and focus in-canvas windows; true fullscreen and a keyboard app switcher support deep work.
  • Global search. ⌘K Spotlight searches apps, commands, notes, files, recent chats and cross-app memory; a > prefix narrows to commands.
  • Dock and menu bar. App launch, app-specific menus, title status, recent work and desktop-level controls sit in persistent chrome.
  • Notifications. Toasts, undo opportunities, a notification center and per-window error boundaries make long work visible.
  • Wallpaper and atmosphere. Creator-owned stock wallpaper, optional Matrix/Core overlays, glass treatments, character models, a monitor widget and configurable notch/provider indicators.
  • Focus and entry. Minimal username → password local gate with skip, optional walkthrough, Help and keyboard shortcuts. The gate provides privacy at the UI level, not storage encryption.
  • Themes. Current source lists four built-ins: Ivory Keep (light), Liquid, Minimal and BMW M (dark). Reduce transparency and material finishes are available.
  • Custom themes. Import a design Markdown, generate validated theme tokens through a selected AI, preview for 30 seconds and save up to 24 themes. Live provider and native visual acceptance remain open.

Source: shell, Control Panel, custom theme guide.

03 / Core app · knowledge

Archives 47

A personal knowledge system built around material you keep: writing, projects, media, relationships between ideas and conversations with your archive.

Capture & organize

Notes that grow into a library

BlockNote rich editing, quick capture, templates, daily notes, tags, favorites, project pages, collections, wiki links and backlinks. Notes support inline AI, callouts and PDF export. Autosave state and retry controls keep failures visible.

Structured work

Databases and views

Property-backed collections have table, board, calendar and gallery views. Today, journal, mood boards and media provide different entry points into the same personal workspace.

Find & connect

Search, Brain and Ask

Full-text and semantic/RAG-style archive search, an Ask Archive interface, link graph/Brain view, and past chat history make stored material useful again.

Learn & investigate

Learn and RepoLens

Learn includes generated lessons, Tutor, mastery estimates, constellations and achievements. RepoLens inspects repositories, builds reports and diagrams, extracts design guidance and includes website reconstruction workflows; the latter remain experimental.

Where it stands

Core note creation, reopen and selected search flows have scoped acceptance. Learn, Tutor, RepoLens, complex databases and media flows still need broader human and provider testing. Notes and files have local crash-draft recovery; an unsaved XDesign or specialist draft does not inherit that guarantee.

Source: Archives navigation, Learn, RepoLens.

04 / Core app · code

Orion

An AI-aware code editor with a conventional developer core. It is the place to open a real folder, inspect and modify files, run commands and review changes.

  • Editor workspace. File tree, tabs, breadcrumbs, Monaco editing, quick open, search, media viewing and editor status.
  • Execution and preview. xterm.js terminal backed by a native PTY, plus a live preview surface for web work.
  • Git. Changes panel, diff review, blame and checkpoints with visible review before applying edits.
  • Language intelligence. Native LSP bridge for diagnostics and navigation; TypeScript, Python and Rust servers are optional installs.
  • AI coding. Context-aware chat rail, codebase indexing/context, inline Claude edits, proposed diffs and Tab autocomplete.
  • Save safety. Atomic file saves, failed-save feedback, permission-sensitive handling and quit protection for known dirty buffers.

Provider boundary: Shared chat can use the selected connector, but inline edits and Tab completion currently use the Anthropic Messages API and a configured key. Real LSP features require external language servers.

Source: editor app, setup and capability matrix.

05 / Core app · creation

XDesign

A single-player design studio that spans editable vector work and generated artifacts. It is the broadest feature area in the repository, and also the area with the most experimental edges.

Canvas

Design system and composition

Layers, inspector, alignment, frames, vector boolean operations, constraints, auto layout, variables, instances, brand tokens, image placement, prototypes and presentation mode. Design-to-code output bridges canvas work into frontend artifacts.

AI creation

Pages, decks and images

AI rail flows can make editable design plans, self-contained webpage previews, slide decks, vector illustrations and raster images. Pages are persisted with project documents; deck output includes HTML/PDF/PPTX paths. Generated output needs review before real-world use.

FX lab

Motion and shader scenes

A WebGL2 compositor provides source layers, blend modes, filters, generators, presets, keyframes, bindings, custom GLSL, audio reactivity and live video sources. It can export PNG, video, standalone HTML embed and scene JSON. Advanced output is still experimental.

3D lab

Reference to model

Model Studio contains a procedural image-to-3D pipeline with reference images, sculpt specifications, geometry/material passes, multi-angle checks, comparison sheets and an assist panel. This is an experimental reconstruction workflow, not general 3D parity.

Project choices in the current UI

New project offers Blank canvas, Webpage, Slide deck, Motion, Image generator, FX scene and 3D model. Webpage, Motion and 3D are explicitly labeled experimental in the app; FX distinguishes tested basics from advanced output.

Acceptance boundary: Basic canvas editing, selected FX and specified export paths have bounded checks. Advanced shader, motion/video/audio, image-to-model and website generation are not certified end-to-end across providers or machines. FX video source export freezes source frames in still/embed paths.

Source: project start menu, app routing, FX, Model Studio.

06 / Shared intelligence

AI is a system service, with deliberate exceptions.

The core apps and R.O.S.I.E. share provider-qualified model selection, streaming chat, app-specific context and tool policy. Control Panel handles providers, agents, skills, API keys, MCP servers and per-surface choices.

Connectors

Bring your account

Claude CLI, ChatGPT/Codex CLI, Gemini CLI, optional Cursor SDK and configured API/local HTTP providers are represented. Subscription accounts and API billing are distinct; availability depends on the connected account and model.

Orchestration

Agent Forge + skills

Build agents with instructions, models and skills. Shared chat applies context and grant policy; a no-grant agent is chat-only. The Skill Library manages selected capabilities and explicit use in Orion turns.

Memory

R.O.S.I.E.

A cross-app assistant can catch you up on recent workstation activity. Spotlight also exposes shared memory from apps and conversations.

07 / Additional apps & extensions

An expanding workstation, carefully staged.

Optional built-in app

Command Center Specialist

An agent organization interface with profiles, divisions/channels, autonomy levels, plans, an organization graph, artifacts and per-profile vault memory. It uses its own pi runtime and credentials. Live end-to-end acceptance remains limited.

Optional built-in app

Hermes Specialist

A task and agent floor/board: create tasks, assign agents, dispatch, stop, inspect logs and read reports. The backend remains Claude-native and requires separate lifecycle and credential testing.

Current worktree

Incubator In source

Inspect local folders or public GitHub sources, review pinned documents without running repository code, request a consent-bound AI assessment, and route supported skills into Skill Codex. Review plans and analysis history remain local; they do not install code or grant tools themselves.

Current worktree

Plugin SDK In source

Built-in apps use an internal plugin registry. A local community SDK has sandboxed UI/runtime contracts, reviewed native grants and a manager for disabled install, enable, update, rollback and removal. A sample lifecycle passed isolated native checks; broad security and compatibility acceptance remain open.

What the importer can and cannot promise

Current worktree code supports versioned skill packages, bounded local package intake, update/rollback previews, persistence recovery and workspace grant checks. It does not automatically transform an arbitrary repository into a working app, run untrusted local engines safely, reproduce upstream feature parity or provide a community marketplace. Repository and remote-tool adapters still need concrete owner fixtures and acceptance.

Source: Incubator, capability importer handoff, SDK guide.

09 / Technical foundation

Local data, native capabilities, explicit recovery.

Stack

Tauri 2 + React 19

Vite/TypeScript UI, Rust native backend, SQLite persistence, Zustand stores, Monaco, BlockNote, xterm.js, Three.js and WebGL2 where appropriate.

Data integrity

Save and recover

Atomic file saves, tracked dirty state, quit guard, retryable note/project saves, scoped note/file draft journaling and verified startup SQLite snapshots with rotating retention.

Release pipeline

Verification gates

Type checks, frontend/bridge/native tests, production build, dependency audits, license material checks, recovery rehearsal and packaged native policy checks support the alpha process.

Recovery has a real boundary

Startup SQLite backups and a restore-to-new-directory command are implemented. Saved webpage HTML now lives in project documents in SQLite. Database copies do not include all media, WebKit state, keychains, CLI accounts or unsaved specialist drafts. Full-profile restoration for arbitrary historic users and power-loss durability are not certified.

Platform and licensing

The public DMG targets Apple Silicon macOS and is ad-hoc signed, not notarized. Original code and creator-owned assets are Apache-2.0; third-party content and optional runtimes retain their own terms. Bundled notices and matching source materials are part of release checks.

Source: native crate, package scripts, alpha gates.
